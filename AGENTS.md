- Локальная ветка: `codex/local-development`. Кандидат 0.8.1-alpha.1 согласует региональную идентичность биомов, локальные местообитания, нативный снег, прибрежный biome continentalness и лесные переходы. Стартовый `minecraft:normal` остаётся FreshGenerator. Физическая пещерная схема 0.7.2 сохранена побайтово: широкие камеры ограничены `min(H−40,20)`, верхние проходы используют постоянное по Y поле тех же link-шумов, соединённое с глубокой сетью на Y0, потолок доступа равен H. Собственная система воды остаётся удалённой; проверяется именно нативная вода Minecraft. АД и Край исключены из текущей переработки по последнему уточнению пользователя.
- Кандидат 0.8.2-alpha.1 (17.11.2026, SHA256 `f4d5fd9cce8aea413a3b52adf78588927db105a9af438561ff3317e84f91dc85`) добавляет слой `TerrainRealismCompiler` поверх 0.8.1: береговой пол добавочного рельефа на нативных сплайнах от `native_height` (`core/CoastalRelief`), «рельеф дна» только ниже H52…60, непрерывная пригодность айсбергов по температуре, маска скальной детали `max(mountain_mask, landscape/mountain)` с интерполяцией 4×4×4, плавный изгиб климатических границ, чистка мёртвых записей `EcotonePolicy`. Повторные ссылки на тяжёлые узлы ландшафта в графе 26.3 пересчитываются: многократная ссылка на корень ландшафта или `coast_height` замедляла генерацию в 2,7–5,7 раза. Новые узлы должны читать тяжёлые входы один раз (сплайны, `range_choice`) и проходить бенчмарк против предыдущего SHA. Пещерная схема и все 26 пещерных ресурсов побайтово равны 0.8.1 по решению пользователя: глубокие пещеры защищают от зависшей воды. Состав проверяет `scripts/validate_terrain_realism.py`, документ — `docs/terrain-realism-0.8.2.md`, нативные прогоны — `FreshGenerator-Workspace/realism-0.8.2-2026-11-17`.
- Кандидат 0.9.0-alpha.1 (18.11.2026) заменяет пещерную сеть 0.6–0.8 в текущем мире на `KarstCaveCompiler` (`core/KarstModel`): три яруса, провалы и шахты, залы с колоннами, каньоны, лабиринты, редкие входы только при H ≥ 73 и кровля ≥ 14 блоков. Пещеры по-прежнему глубокие и не выходят на поверхность массово. Решение пользователя от 18.11 разрешает редкие логичные входы. `CaveNetworkCompiler` остаётся для исторических тестов. `ClimateNicheCompiler` ограничивает только оси выбора биома: сухой пояс влажности при T 0,46…0,55, потолок эрозии болот выше H72. Не ограничивать саму температуру выбора: это убирало лесистые бедленды и тёплый океан. `BiomeReliefCompiler` поднимает рельеф по климатическим полям биома: столовые горы бедлендов, холмы ветреной полосы; только поднятие. Итоговый SHA `ac9423cc…` (от обследованного `4650b373…` отличается только описанием в `fabric.mod.json`). Лесные исправления 6.1–6.7 внешнего аудита и запрет расширять кроны за нативный максимум (распад листьев дальше 6 от бревна) закреплены тестами. `rock_relief` не входит в активную плотность: не править её ради «детали гор». Шумы низкой частоты в 26.3 имеют большую амплитуду. Пороги и глубины входов выражены через пересечения линий шума и блоки, а не через уровни шума. Состав проверяет `scripts/validate_karst_caves.py`, документ — `docs/caves-0.9.0.md`, прогоны — `FreshGenerator-Workspace/caves-0.9.0-2026-11-18` (наблюдатель `KarstCaveAudit`).

## Сборка на этом ПК

Параметры проекта: Minecraft Java 26.3, Fabric Loader 0.20.1, Fabric API 0.165.2+26.3, Java 25, Gradle 9.8.2.
Системная Java при подготовке была версии 8; для сборки использовать локальный скрипт, который задаёт Java 25 только на время команды.
В локальных настройках репозитория отключён `core.autocrlf`: проверки опубликованных исходников требуют точного совпадения байтов с Git, включая окончания строк.

```powershell
& 'D:\Codex\00CODEX\FreshGenerator-Workspace\dev.ps1'
& 'D:\Codex\00CODEX\FreshGenerator-Workspace\dev.ps1' test
```

Без аргументов выполняется `build`. Выходные JAR находятся в `build/libs`.
Скрипт использует имеющийся в репозитории Maven fallback без замены закреплённых версий.

Python-проверки запускать с Java 25 в JAVA_HOME и PATH; команда из корня проекта:
`python -m unittest discover -s scripts -p 'test_*.py'`.
Часть инфраструктурных Python-тестов требует Bash и возможности создавать символические ссылки; учитывать ограничения Windows при разборе ошибок.

## Проверка результата

Запускать проверки, относящиеся к изменению. Не выдавать исторические результаты из документации за новый локальный запуск.
Обычная сборка и модульные тесты не заменяют серверную матрицу генерации, сохранения/загрузки, поведения воды, деревень, структур и Distant Horizons.
Нативные доказательства 0.8.0 разделены по SHA: широкий кандидат b142c0… обследован в 18 участках, итоговый 226df1… содержит только точечное исправление OPEN_GROVE для вишни; прочие 28 профилей совпали в 5600 побитовых сравнений. Итоговый JAR отдельно проверен на вишнёвой роще, сохранении/загрузке, пещерной связности и горном грунте. Не выдавать широкую матрицу за повторный прогон всех участков итогового JAR. Изначальный наблюдатель стволов ошибочно допускал листву как опору: итоговые числа — офлайн-пересчёт полных сохранённых материалов строгим классификатором, исходные данные сохранены.
Не объявлять визуальную естественность рельефа доказанной только по числовым тестам.
Текущий пользователь требует независимые сиды и проверку каждого биома обычного мира; один удачный сид не доказывает исправление. Промежуточное ручное тестирование пропускается: пользователь проверяет готовый мод. Собственную воду не создавать, АД и Край не перерабатывать. Инвентаризация всех ID не равна приёмке FULL-генерации. Нативные параметрические траектории не являются реальными пространственными границами.
В 0.8.1 карты климата и FULL-поверхность имеют разную доказательную область. Восемь sampler-прогонов 04a4 допускаются только при явной проверке идентичности соответствующих density/noise ресурсов и нативной parity-проверке итогового JAR. Пакетные, почвенные и лесные доказательства относятся к собственному SHA. Не выдавать полную перестановочную детерминированность декораторов за доказанную: в регрессионном случае поверхность/биомы совпали, а нативные руды, комнаты и травы дали отличия. Сохранение/повторная загрузка проверяется отдельно.
Кандидат `3877532b3d1e7ef64f1f7563bee21ae395169b0f41ac0f1ae44c3128e471be7a` дополнительно исправляет потерю нативных point-filters при заимствовании древесной палитры. `NativeForestPalette` сохраняет исходные `BlockPredicateFilter`/`SurfaceWaterDepthFilter`, не повторяет смещение/count/heightmap/чужой BiomeFilter и отказывается от непроверенных/неизвестных схем. Возврат сырого `Feature` вместо проверенного `PlacedFeature` ранее позволял `soil_beneath_tree` создавать dirt под новым стволом в чужой кроне. Это доказанная ошибка адаптера, не предел симуляции Minecraft. Контакт ствола с soil не доказывает опору этой soil; проверять связь реального грунта и сохранять цензурирование краёв. Нативные диагональные углы `forest_rock` и глубокие каменные фрагменты учитывать отдельно, не маскировать под ноль. До-правочная матрица f028/3bd хранится отдельно; новая FULL-матрица должна иметь фактический SHA3877, без переноса прежней лесной class-parity.
Статус первоначальной настройки и журналы находятся в соседней рабочей зоне.
